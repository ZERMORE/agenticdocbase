## 1. 主题与摘要

文件：`3974D90A4FFC8D21E847816B7B528C13.png`

- 标题：基于 AI Agent 的个人本地多模态文档智能问答系统。
- 副标题：doc2md × DocBase × AGENTS.md——让沉睡的本地文档“开口说话”。
- 场景：个人保存大量 PDF、Word、PPT，多模态内容在忘记位置与文件名后难以找回。
- 路线：CodeAgent 开发 Python 脚本；预解析本地文档，构建 RAG；通过 AGENTS.md 指导 Agent 使用知识库，实现内容查询与精准溯源。
- 技术栈：CodeAgent、RAG、Embedding、Reranker、Chat LLM、VL。
- 模型名：Qwen3-Embedding-8B、Qwen3-Reranker-8B、GLM-5.1、Qwen3.6-27B-VL。已对模型区域放大核对，仍需在实施时确认接口。

## 2. 系统总体架构

## 3. 五步实施路径

文件：`7BF1830199AF356C95CD6FA1638192DA.png`

1. 文档格式转换工具 doc2md：一键转 Markdown，提取图片，VL 解析写回 MD，保留原文链接，按文档名/Page/Figure Title 命名。
2. RAG 工具 DocBase：切片入库；稠密向量+BM25+BGE-M3；RRF+Reranker；build/query/test；多文档与分类。
3. AGENTS.md 知识消费约定：规定检索时机、组合方法和引用原文方式；输出回答与溯源。照片还提到 `DocBase/CLAUDE.md` 配置示例。
4. 后台 Service：定时/增量更新、文档和索引管理、监控目录与单文档解析。
5. B/S Web：图形界面；后台无头调用 CodeAgent，照片举例 `claude -p / nga run`。

前三项标为基础必做，后两项标为可选扩展；“已完成 Demo”是课件对演示项目的描述，不是当前目录已经包含相应实现。

## 4. doc2md 解析引擎

文件：`C24B928AFAF187B5F12D05C5023ED43A.png`

- 多格式输入、统一 Markdown、图片提取、VL 释义、写入 MD、结构化输出。
- 位图直接 OCR，矢量图先渲染；理解模块、箭头、编号等图像关系。
- 图片释义保留在原图上下文，切片后仍保留图文语义。
- 保留文档名、页码、图题和原始文档链接，支持逆向定位。
- 后续可扩展 Visio、Drawio。

左侧部分内容在照片中出框，但主要流程和右侧能力矩阵可读。课件“技术文档中约 30%～50% 关键信息以图片承载”未附测量来源，应作为背景陈述，不作为本实验统计事实。

## 5. DocBase 三路混合检索

文件：`2A997E8EC0F79AD82029008BC30CEE77.png`

上半图：Markdown 文档集 → 语义切片 → Qwen3-Embedding-8B → BM25 与 BGE-M3 索引 → 本地持久化/增量更新，并显示进度。

下半图：稠密向量、BM25、BGE-M3 三路并行 → RRF → Qwen3-Reranker-8B → 含来源的 Top-K → Agent 综合回答；test 用于检索质量自测。

理由：精确术语适合关键词检索，语义问法需要向量；融合并精排兼顾两者。底部左侧部分文字被人物遮挡。

## 6. AGENTS.md 让 Agent 学会查资料

文件：`35346282D5F199C44505B2DA2D407FE7.png`

- 声明知识库存在，规定何时查、怎么查、如何引用，将人的检索经验变成工作流。
- 图示的逻辑流程：问题 → 意图分析 → RAG 查询 → 不足时补检 → 筛选证据 → 综合推理 → 结构化呈现 → 溯源。
- 约定示例：领域问题先检索；按分类缩小范围；技术名词用 BM25，原理问题用向量；带文档/页码/图号；无据不答；流程问题生成 Mermaid 并和原图核验。

页面以 S 形排列流程框，不能把上下两排的横向位置简单当作线性执行顺序。底部引用要求左侧局部被遮挡，可结合另一张开发视图交叉确认其含义。
