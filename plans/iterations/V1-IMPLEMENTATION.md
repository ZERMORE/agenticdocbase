# V1 质量版实现与验收说明

代码目录：E:/project_files/agenticdocbase。迭代方案见 Obsidian 的《01 质量版实施方案》。本文件记录实现边界，实际测试结果另存 V1-VALIDATION.md。

## 使用方式

启动根目录 start.cmd，浏览器访问 http://127.0.0.1:8765。

1. 知识库 → 按解析质量筛选 → 点击文件 → “质量与修订”。可查看页级统计、待处理块与风险。旧产物只读计算报告，新产物自带 quality.json。
2. 选择文字块、填写修正文字和原因，保存纠错；或指定页序号只重跑这一页；或选择 image 区域补识别。默认离线，外部识别需先启用库级授权。
3. 任务中心跟踪“内容修订”，完成后发布新索引；重新打开质量页或点刷新查看。原PDF和旧产物不改，历史引用继续绑定旧快照。
4. 点击聊天引用，自动生成原页定位图：文字匹配、块区域、仅页码三种状态明确区分。PDF原生阅读器仍可使用。文字匹配可能有多处，不宣称唯一字符级定位。
5. 新网页问答默认启用模型辅助支持性检查，受同一总时限和调用预算限制；最多修复一次，仍不支持的结论移除。检查失败或预算不足标“未核验”。历史答案不会补跑模型。
6. 个性化设置 → 备份与恢复，可保存定期备份策略或排队手动备份。自动备份仅空闲时执行，保留策略只清理登记的自动备份。失败原因和上次备份可见。

CLI 可选核查：

```bat
cd /d E:\project_files\agenticdocbase\DocAgent
run.cmd ask --collection zotero_third_20261028 --question "CLIP-Adapter如何调整模型？" --verify-support
```

该命令会调用已配置模型；构建验收未替用户执行。支持性检查使用同一已配置模型，属于自动辅助判断，不能当成人工事实认证。

## 兼容性与来源契约

- 旧 source.page_index 继续从1开始；新增 quality/locator.page_index 从0开始，UI另有 display_page。未重写旧来源或索引字节。
- revision 保留源文件 SHA256；派生产物由独立 config_fingerprint 和内容哈希区分。lineage 记录替换块，未变块保留原ID。
- 人工纠错在检索和上下文中标 human_correction，不冒充PDF原生文字。定位到原PDF时可能只显示块区域。
- 连续全文PDF解析每页完成写检查点；中断后任务重试复用同一输出目录，跳过已完成页。Office原生、单幅图像和局部修订不提供页级恢复，重试重新执行对应操作。
- 网络超时与HTTP5xx不自动重放Agent请求；明确429限流有限退避并尊重Retry-After。图像模型同样仅对429有限重试；超时、5xx和无效响应不自动重放，成功结果继续复用缓存。
- SQLite schema_version 升级2，保留既有业务表，增加修订/备份记录。恢复支持旧备份，无数据库哈希的旧备份不能获得新增哈希保证。
- API/worker日志启动时超过10MB轮转，保留3份。任务诊断提供分类与建议，不自动重放问答。

## 评估门槛

evaluations/README.md 提供候选生成、审核、冻结、离线诊断命令。60题候选不等于60题人工标注；正式命中率、回答支持率与拒答率必须在审核冻结后实测。当前实现不将这些未完成的人工验收宣称为达标。

## 回退

构建前已停止服务并生成数据备份。代码改动保留在Git工作树，未自动提交。先备份当前数据；回退代码后若不兼容新schema，应恢复构建前备份到新的不存在目录，设置 RESEARCHDESK_DATA 为该目录，再启动并检查资料、索引和历史引用。禁止直接删除旧来源或在原库覆盖恢复。
