# V2 体验版：实现与使用

更新：2026-10-30。工程功能已落地；真实模型流兼容性及正式检索质量验收另行记录，不能以离线测试替代。

## 使用入口

在项目根目录运行 `start.cmd`，浏览器打开 http://127.0.0.1:8765。更新前端后用 Ctrl+F5 刷新。四个 Conda 环境继续隔离。

| 需求 | 操作 |
|---|---|
| 流式回答 | 设置 → 模型配置 → 问答 Agent → 输出方式选“优先流式”。不支持时整段返回；断流不自动重发计费请求 |
| 区分草稿 | 灰色草稿明确标记“尚未核验”。最终结果仍通过原文引句校验，支持性强度沿用你的设置 |
| 改问题 | 问题上方“编辑并创建分支”，修改输入框后发送；原问题和回答保留在原分支 |
| 重新生成 | 回答下方“重新生成”，创建新分支并提交同一问题；会产生新模型请求 |
| 回到原答案 | 会话顶部“对话分支”选择原分支；只将当前分支祖先传给 Agent |
| 收藏 | 回答下方“收藏回答”；打开引用后可“收藏此引用”。左侧“收藏”可返回所属上下文 |
| 导出 | 会话顶部导出 Markdown 或 JSON；包括消息关系、状态、配置版本、范围快照和可追溯引文 |
| 论文信息 | 知识库文档行 → 文献信息与标签，填写标题、作者、年份、DOI、渠道、标签。多个作者/标签用半角分号分隔 |
| 筛选 | 知识库列表按作者、标签、年份筛选；聊天“限定资料”也可筛选和多选。空集不会退回全库 |
| 试验补检 | 设置 → 回答偏好 → 术语补检。默认关闭；仅追加固定英文术语，不改范围。答案可展开本轮实际查询和候选片段 |
| 换模型/Key | 设置 → 模型配置，分角色保存。Key 留空保留，勾选清除才清除；更换域名须重新填 Key |
| 测试连接 | 显式点击“测试已保存配置”，确认发送合成短文本；结果见任务中心。不发送论文，但会调用所配置供应商 |

服务首次初始化从三个项目 `.env` 导入模型配置，之后网页任务使用服务端版本化配置；继续改 `.env` 主要影响独立 CLI，不会覆盖网页已保存版本。网页 Key 使用 Windows DPAPI 加密，存于 `ResearchDesk/data/secrets/*.dpapi`，数据库只保存凭据 ID。更换 Windows 账户后需重新填写 Key。

支持核查可沿用问答模型，也可单独设置。问答与检查共享每轮总调用上限；网络重试也计入预算。向量和重排表单提供配置/合成探测，**当前网页仍是 BM25-only**；保存模型不自动切换索引或触发全库计费重建。

## Zotero 增量同步

1. 在 Zotero 导出所需集合为 **Zotero JSON**。附件应具有 `path`/`localPath`，可为 storage:附件键:文件名、绝对路径或相对导出文件的路径；仅复制 PDF，其他条目保留在 Zotero。
2. 知识库页面底部填写 JSON 文件和 storage 目录，添加来源。不会读写 Zotero SQLite，也不会移动原件。
3. 点击“预览变更”，检查新增、内容变化、仅元数据、重复、冲突、缺失和人工移出等状态；再“应用本次预览”。
4. 后台复制 PDF，按 SHA 去重，离线解析并更新索引。相同内容更名、仅元数据更新不重复解析；人工确认字段优先于 Zotero 导入。
5. 需要自动跟随时显式启用自动同步，每分钟读取 **该 JSON 文件**。它不能自动导出 Zotero 当前数据库；你需要更新该导出文件。可随时暂停。
6. 缺失/离线保留库内资料；人工移出的资料不会自动恢复。预览后文件有变化会要求重新预览。同步任务按附件检查点恢复；停止任务和暂停未来自动扫描是两个操作。

本次未擅自将整份 Zotero 库重新入库，也未创建实际同步来源；现有33篇论文和示例仍保持原有范围。

## 架构

前端 `main.tsx` 只组装工作空间；`controller.tsx` 管理会话、任务、上传等动作，`WorkspaceContext.tsx` 共享工作空间状态。页面为 ChatPage/LibraryPage/TasksPage/SettingsPage；新增 V2Chat、MetadataPanel、ModelSettings、ZoteroPanel，既有质量修订和定位组件复用。

服务 `v2_store.py` 负责增量 schema-v3、祖先链、元数据；`v2_routes.py` 负责分支/收藏/导出/同步/配置接口；`model_profiles.py` 管理不可变配置版本和 DPAPI；`zotero.py` 负责只读预览/增量应用。API 与 Worker 保持既有任务租约和取消检查。

DocAgent `streaming.py` 组装 SSE 工具参数，只公开 `submit_answer.claims[].text`，不转发隐藏推理、原始工具参数或引句。工具参数仍完整校验后才发布答案。`query_terms.py` 提供默认关闭的术语实验。

SSE v2 含 event_id/job_id/message_id/run_id/sequence/data，支持 Last-Event-ID 续传。草稿独立存储，不写入最终答案；终态草稿与流事件保留7天，最终消息、证据与范围快照继续保留。后台进程超时/断流不会自动重放问答。

任务冻结 branch、allowed_doc_ids、索引、generation、偏好和各模型 revision。后续元数据、移出/撤权/同步改变范围时取消旧任务；子进程通过环境接收该版本凭据，命令行不含 Key。

## 升级与回退

本次升级前备份：`ResearchDesk/data/backups/20261030-002230-1fe6ae52`。schema-v3 仅添加侧表，未覆盖旧消息/文档产物；既有会话迁为主分支。

回退先停止工作台，使用 Git 保留本次变更再选择先前提交。通过 `researchdesk restore --backup-path ... --destination ...` 恢复到**新目录**，按既有恢复说明指定 RESEARCHDESK_DATA；不要覆盖当前数据库。旧版程序不应直接打开正在写入的 V2 数据库。

V2 备份包括加密凭据；同 Windows 账户恢复可解密，跨账户重新填写。恢复后目录监控和 Zotero 自动同步均暂停，先核对路径再启用。
