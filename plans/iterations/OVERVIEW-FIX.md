# 全库概览与PDF引文修复记录

日期：2026-10-29。触发问题：“概括这些论文的主要研究方向”。

## 查到的实际原因

1. 原问答范围确有33份文档。普通BM25使用中文问题检索英文论文库，大量中文通用词只匹配一份中文开发文档，后续补检沿手语/唇语继续偏移，结果22个证据块仍来自1个文档。不是只选了一份资料，也不是文档全部丢失。
2. 首次失败两轮各16个引文，主要是中文行内换行导致错误拒绝；修复后的历史离线重放全部匹配。后续真实验证又发现PDF ﬁ/ﬀ 等字形连字和英文软连字符，旧规则同样不完整。已限定到排版等价处理，保留原始字符映射，不允许同义改写、数字或否定变更。
3. 多文档长回答两次耗满2500输出token，JSON被截断却报“参数格式错误”。现在识别finish_reason=length，有独立缩短修复和明确失败原因；概览要求少量主题、简短引文，不逐篇展开。
4. 模型支持性检查理由有时承认缺证据仍返回supported。已要求整条claim每个事实有据；明确承认缺失支持时保守降级，不给完整支持徽标。

## 实现

- DocBase增加只读overview：固定索引，逐文档校验不可变来源，以摘要/正文头尾代表片段保留背景与贡献；独立准确字符跨度，不依赖问题语言。
- DocAgent路由集合概览，单篇问答保留原路径；所有取样和补检遵守allowed_doc_ids、category、固定索引和字符预算，空范围不回退全库。
- 概览展示范围、取样和引用文档数。引用覆盖不足时要求修复；未补足或取样不全则标证据不足。最小引用文档门槛是防止单篇冒充全库的工程保护，不是主题全面性或正确率指标。
- repair反馈列出多个不匹配引文与原文候选，不只修一处再因下一处报错。PDF连字展开两侧必须对应原始字符边界。
- 新增请求预算只能降低配置预算；HTTP重试也计入总请求上限。
- docagent.revalidate仅本地重验已完整返回的概览提交：重新验证固定索引、来源摘要、原句与字符跨度；派生新运行，不改旧记录，不调用语言模型，不伪造语义检查。

## 实测与授权

相关145项回归通过：DocAgent70、DocBase44、Service31；前端构建通过。浏览器确认覆盖统计、恢复说明、引用定位和小屏无横向溢出。doc2md本轮未修改，沿用先前47项结果。

初次申请真实复测被自动审批拒绝，随后用户明确授权向api.deepseek.com发送该33份文档的代表片段与同题，最多6次请求。实际合计6次，未超限。验证期间的中间错误全部保留。

最终输出通过修复后的PDF排版匹配进行离线恢复：取样33/33份，回答引用31份，额外模型请求0。验证会话为“修复验收 · 33份资料研究方向”，最后一条为恢复结果。之前的失败消息没有被删除或伪改为成功。

这份结果只做了来源、原句与跨度核验；没有再进行独立语义检查，UI明确标为未核验。模型主题归类可能交叉，不能把取样/引用数量当正确率，也不能声称已逐篇读完全文。此前162项功能验收没有覆盖这个真实问法，是漏测；现已增加跨语言全库概览、覆盖保护、截断、PDF字形和离线恢复回归。
