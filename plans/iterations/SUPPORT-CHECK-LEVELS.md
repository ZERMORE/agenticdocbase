# 支持性检查强度设置

网页路径：个性化设置 → 回答偏好 → 支持性检查强度 → 保存偏好。

| 档位 | 行为 |
|---|---|
| 关闭 | 不额外调用模型作语义支持检查；原文引用匹配、来源和范围校验保留 |
| 宽松（网页默认） | 保留引用合法的回答，显示模型判断的支持风险；不因语义检查意见自动删主题 |
| 标准 | 支持不足只提示；明确矛盾才触发修复，未解决则仅交付部分结果 |
| 严格 | 支持不足和矛盾均触发修复；未解决的结论移除，并明确标为部分结果 |

选择“全局默认”可影响没有单独覆盖的新旧会话的下一轮；先打开某会话再进入设置，选择“仅当前会话”可设置覆盖。切换保存范围时表单会回读对应设置。设置不会重新调用模型或改写历史答案。

关闭或宽松都不会放行编造引文，也不能保证生成内容正确；区别是额外的模型语义意见是否阻止交付。每条回答记录实际使用档位，模型检查仍是辅助判断，不是人工事实认证。

CLI明确启用：`DocAgent\run.cmd ask --question "问题" --verify-support --support-level advisory`，可选off/advisory/balanced/strict。CLI默认维持旧兼容行为：未加--verify-support时不启用语义检查；加后默认strict，网页默认advisory。

## 本次同时修复的旧问题

- 工具参数中的完整JSON对象若仅多出1–2个末尾右花括号，可确定性去除并再次通过完整严格schema；不改字段、引文、数值，额外文字、多对象和截断JSON仍拒绝。真实新日志中的3次此类错误均已离线回放通过。
- 支持检查补入同一被引文档的全部已登记代表片段及文件定位信息，不再只检查一条背景片段；仍不引入其他未引用文档或模型常识。
- 合理主题归纳可标推断；严格/标准模式删去结论后，不再因“还引用8份资料”就冒充完整回答。页面显示核验完成数量与未完成主题。
- validation_failure是内部核验/修复事件，日志继续保留；界面显示“核验与修复”，不能仅凭这个中间事件认定整轮失败，应看最终状态。
- 截图中8个主题只保留3个的历史回答已纠正为证据不足/部分结果，保留原始运行和纠正前消息快照。
