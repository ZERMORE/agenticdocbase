# doc2md → DocBase 整合接口

2026-10-28补充：已构建并列的DocAgent项目，说明见`../DocAgent/README.md`。新增只读`context --chunk-id ... --index-version ... --before 1 --after 1`、`status --index-version ...`及查询可选`--prefer-body`。context返回独立来源块，chunk_id为null，evidence_kind为context_block；不能将这些块当成既有chunk调用get。新增可选context-v2切片配置，原block-v1和默认query排序仍兼容旧调用。DocAgent的DeepSeek真实接入待填写其独立Key后验证。

两个工具使用不同 Conda 前缀，不共享 .env，也不要求互相导入 Python 包。后续 Service 使用独立子进程调用，跨进程传递 JSON 文件和证据 ID 即可。

## 实际接口

1. doc2md：`parse 输入文件 --output 输出目录`，完成后读取该目录 `batch_report.json`。
2. 对报告中每个非 failed 的文档，取其 `output` 路径。
3. DocBase：`select --artifact 上一步的output路径`，显式设为该 doc_id 的当前产物。
4. DocBase：`build --profile bm25-only --incremental`；模型实际可用后换 hybrid。
5. DocBase：`query --profile bm25-only --question 问题 --format json`，读取 stdout JSON，保存 query_id/index_version/chunk_id。
6. `get --chunk-id ... --index-version ...` 可对同一快照重新取证据。

选择产物后仍按 DocBase 质量规则只索引成功内容。partial 文档的缺失信息保留为质量警告，不能当作完整多模态解析结果。

## 后台调用示例

以下示例说明进程隔离及参数传递，不启动后台守护程序、不安装额外服务：

```python
import json
import subprocess
from pathlib import Path

workspace = Path(r"C:\Users\Lenovo\Desktop\研一\大模型软件开发")
parser_root = workspace / "doc2md"
base_root = workspace / "DocBase"
parser_python = parser_root / ".conda" / "python.exe"
base_python = base_root / ".conda" / "python.exe"
output = parser_root / "output" / "service_example"

def invoke(python, module, args, cwd):
    return subprocess.run(
        [str(python), "-m", module, *map(str, args)],
        cwd=cwd, capture_output=True, text=True,
        encoding="utf-8", errors="replace", shell=False,
    )

p = invoke(parser_python, "doc2md", ["parse", parser_root / "examples/sample.pdf",
                                    "--output", output], parser_root)
if p.returncode not in (0, 2):
    raise RuntimeError("doc2md 失败，检查 stderr 与 JSON 结果")

# doc2md 的第三方 PDF 库可能在终端打印提示；以落盘报告为准。
report = json.loads((output / "batch_report.json").read_text(encoding="utf-8"))
for item in report["results"]:
    if item["status"] == "failed":
        continue
    selected = invoke(base_python, "docbase", ["select", "--artifact", item["output"]], base_root)
    if selected.returncode != 0:
        raise RuntimeError("产物登记失败")

built = invoke(base_python, "docbase", ["build", "--profile", "bm25-only", "--incremental"], base_root)
if built.returncode not in (0, 2):
    raise RuntimeError("建库失败，原有效索引仍保留")
answer = invoke(base_python, "docbase", ["query", "--profile", "bm25-only", "--question", "1729"], base_root)
if answer.returncode != 0:
    raise RuntimeError("检索失败")
result = json.loads(answer.stdout)
print(result["index_version"], result["results"])
```

上例 parse 默认可能调用已配置的视觉模型；只想离线检查进程接入时给 doc2md parse 加 `--offline`。DocBase 的 bm25-only 不调用检索模型。

Service 应按任务管理超时/取消、记录退出码及阶段，不把不受控用户字符串拼成 shell 命令。原生进程示例适用于已验证的基础依赖；本地 CUDA/FlagEmbedding 扩展若依赖 Conda 激活变量，应使用 `conda run --prefix 对应环境` 并单独验证。

## 字段和版本

- doc2md 文件契约：manifest、blocks 的 schema_version=1；source 的相对路径相对于该文档产物。
- DocBase source_store 会复制并校验原文/图片，旧索引不依赖 doc2md 可变输出目录。
- query 输出 schema_version=1，status=ok 并不表示问题必然可答；results 只是相关证据。
- 当前可用模式为 bm25-only；hybrid 代码已实现但实际模型调用受平台账户资源限制；full 还需要真实 BGE-M3 sparse。
- 变更来源版本用 select + build，查询固定 CURRENT 对应的一个完整快照，旧版本仍可 get。

不建议通过激活/反激活环境在同一服务进程中切换 Python 依赖；保持双进程接口更便于后续 Web/Agent 整合和故障定位。
