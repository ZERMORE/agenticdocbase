# 研知 / Research Desk

本机知识库与 Agent 聊天工作台。整合现有 doc2md、DocBase、DocAgent，网页采用瑞士国际主义极简风格：黑白、信号红、强网格、文字层级与编号引用。

## 直接使用

本次已安装依赖、构建网页并启动服务，浏览器打开：

**http://127.0.0.1:8765**

以后从 CMD / Anaconda Prompt 启动：

```bat
cd /d "E:\project_files\agenticdocbase\ResearchDesk"
start.cmd
```

停止用`stop.cmd`，检查进程记录用`status.cmd`。关闭浏览器不会停止后台。首次安装或重建依赖用`setup.cmd`，已有模型Key不覆盖，不重装前三项目环境。setup要求电脑已有Conda和兼容Node，当前已验证Node22.13.1与Vite7.3.7。

## 先体验已有资料

左侧“知识库”已有：

- Zotero · 论文资料：33篇，继续使用已有解析产物，没有重新调用模型解析。
- 示例 · 工具验证：sample.pdf，用于核对版本号1729。

## Agent 聊天

1. 在聊天页选定知识库；需要限制资料时点击“限定资料”，选择具体论文，否则默认检索全库。
2. 首次使用某库的外部模型前，进入“知识库”勾选“允许此知识库使用外部模型”。这是持久设置，可撤回。
3. 回到聊天输入问题。Agent会自主检索、补查上下文并生成带引用的回答。
4. 点击`[E1]`等引用，右侧展开原文短句、文件、页序号和PDF预览。可新窗口打开原文。
5. 支持追问、停止、复制、重新生成、导出、会话搜索/重命名/删除；刷新保留历史。

**外部模型处理**：问题、最近会话及选中证据会发送至DeepSeek；选择完整解析时，必要页面/图片会发送至doc2md配置的Qwen服务。默认没有替用户开启任何知识库的外部处理。本地内容检索和离线解析不需要开启。

DeepSeek Key继续读取`../DocAgent/.env`的`DOCAGENT_API_KEY`。doc2md Key在其自己的.env中；网页不会显示Key，Service不复制凭据。已配置过时不用重新填写。

回答先显示真实阶段状态，再交付经过引用校验的最终内容，当前没有逐字模型流。引用校验验证来源与原文匹配，不等于对每项结论做完人工事实审核。

## 个性化

“个性化设置”可调整中文/英文、简洁程度、研究背景、研究方向、先结论或先解释。支持默认偏好与当前会话覆盖，下一轮生效，历史答案不改写。

上下文保留最近8条有效消息，较早部分采用用户问题摘录作为主题索引，不将历史模型回答当原文证据；不是无限记忆或自动形成个人画像。切换知识库会开始新会话，避免资料范围混杂。

## 上传、浏览与删除

- 支持PDF、DOCX/PPTX、旧DOC/PPT、PNG/JPEG入口，实际解析能力取决于现有doc2md依赖；旧Office转换缺少LibreOffice时会明确失败，不假装已支持。
- 每文件100MB、每批20个。默认“仅离线文本解析”，完整解析需允许外部处理。
- 上传完成后后台继续解析、建库；只有“可检索”才表示索引已发布。重复上传相同内容不会在同库重复登记。
- 文件列表支持名称筛选、当前/已移出状态、分页、预览与离线重解析。
- 内容检索只返回片段，不调用DeepSeek；点击“基于当前知识库继续问”进入聊天。
- 文档预览可切换原文、Markdown、图片。PDF使用浏览器原生阅读器，支持Range与页码；Office原文件提供打开/下载，浏览器能否预览取决于其能力。
- “移出”立即从新检索范围排除文档，后台重建索引；最后一篇移出会发布空索引，绝不回退旧内容。可以切换“已移出”列表恢复。
- “回收知识库”隐藏该库、停止相关任务，保留原始文件与历史快照。首版没有提供彻底擦除文件功能，避免误删Zotero原件或其他库共享的快照。

部分论文为partial，表示只有部分内容解析完成；未命中某章节不一定说明该章节没有入库。首次中文检索可能不够准确，Agent可补检英文术语，但整体论文质量仍需人工冻结题集评测。

## 任务与目录监控

任务中心显示解析、建库、问答的排队、阶段、失败原因。可以停止任务；非问答任务可重试。问答失败请在会话中重新发送/生成，不自动重放整轮计费请求。

偏好设置页底部可登记本机具体资料目录，每分钟扫描。首次登记会导入该目录下支持格式的文件，请选择合适大小的目录；默认离线解析。文件变化时按内容版本更新，原文始终只读；目录掉线或源文件消失不会自动批量删除库内资料。可暂停/恢复监控。

后台使用单个持久Worker，任务按知识库串行，API独立运行。已入库资料可在更新期间查询旧完整版本。重启后过期任务标记中断，可重试；不静默重复执行已发生的问答调用。

## 数据在哪里

```text
ResearchDesk/data/
  app.sqlite                 知识库、成员、会话、偏好、任务和引用映射
  uploads/                   网页/监控托管原文
  parsed/                    新解析产物
  catalogs/                  各库独立catalog
  runs/                      工具输出、Agent原始答案与任务日志
  logs/api.log、worker.log    服务运行日志
  backups/                   手动备份
DocBase/storage/
  indexes/rd_kb_.../          工作台的版本化索引
  source_store/              不可变原文/图像快照，历史引用使用
```

API只返回受控asset_id，浏览器无需也不能用file://访问任意磁盘路径。Markdown中的图片通过单独图像页签查看，原始HTML不执行。

## 备份与恢复

运行`backup.cmd`，生成数据库快照、文件包及SHA清单，不打包.env；备份可能较大，因为包含历史引用所需的共享source_store。建议在没有运行任务时备份。

恢复到**不存在的新目录**，不会覆盖当前应用：

```bat
service\.conda\python.exe -X utf8 -m researchdesk restore --backup-path "data\backups\备份目录" --destination "E:\project_files\agenticdocbase\ResearchDesk\recovered-data"
```

使用前先`stop.cmd`，在CMD中设置`RESEARCHDESK_DATA`为恢复后的绝对目录，再`start.cmd`。恢复过程重映射托管资源、索引和来源目录，刷新本机会话凭据，暂停目录监控，将未完成任务标为中断。保留`restore-mappings.json`用于检查；恢复后先检查资料预览和检索，再开启新问答。

可选的`install-autostart.ps1`用于当前用户登录时启动，默认没有执行；显式运行后注册名为ResearchDesk-Local的Windows任务。不是必须步骤，也未修改系统执行策略。

## 验证与边界

- 后台接口/持久队列/监控/备份恢复自动测试；前三项目相关回归测试。
- `service/scripts/smoke_workflow.py`是本地离线真实工具链验收，会新建并回收一个验收知识库。
- `web/e2e.mjs`检查真实页面、导航、已有历史答案及引用，在1440/1024/390宽度截图，不请求模型。
- `design/screenshots`保存页面截图，`design/browser-report.json`及`workflow-report.json`保存结果；Taste报告在`design/taste-audit`。

本次构建没有新增外部模型请求。网页到真实模型的首次新问答、多轮答案质量和完整图像理解需用户开启对应库授权后实际检查。

首版本机单用户，固定127.0.0.1:8765，没有多人账户/权限体系，不开放公网；没有彻底物理删除、Token逐字流、自动原图核验或云部署。数据库采用SQLite原生事务和版本表，未引入SQLAlchemy/Alembic；PDF采用浏览器原生阅读器，未引入PDF.js。上述是此次实际实现与方案中可选技术选型的差异。
